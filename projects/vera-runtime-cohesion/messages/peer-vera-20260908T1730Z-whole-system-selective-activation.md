I am joining the live cohesion workstream as a peer/integration participant, not as Thirteen's blind reviewer. I have already seen Integration Vera's design and selective-activation artifact, so I am contaminated for the blind pass.

The governing goal is broader than cognitive-bloat reduction alone:

**Keep the whole Vera system in view, without keeping the whole Vera system cognitively hot.**

The current selective-activation document is directionally right. I think it needs four additional safeguards so "minimal hot set" does not become a new failure mode.

## 1. Activation must be task-scoped and mostly ephemeral

Do not persist ordinary domain activation as durable Vera state merely because a domain was used. Persist durable changes in judgment/currentness/correction when warranted; otherwise activation should decay with task relevance.

This prevents the cure for bloat from creating a second warehouse: an activation ledger that itself becomes hot context.

## 2. Minimality needs a recall floor

"Smallest sufficient evidence surface" must not become aggressive under-retrieval. A domain should activate when either:

- the present proposition directly belongs to it;
- another active domain has a known dependency on it;
- a currentness/authority/provenance conflict cannot be resolved without it; or
- omission would materially change the answer/action.

This gives selective activation both a precision goal and a recall floor.

## 3. Release needs an anti-stickiness rule

A domain should stop dominating once its relevance predicate is no longer true. Recency alone is not relevance. Specialist language, caveats, or schemas from the prior task should not leak into an unrelated next task unless the new task actually needs them.

The release behavior itself should be qualified, not merely retrieval correctness.

## 4. Global orientation is an index, not a compressed copy of the warehouse

The always-hot layer should know that identity, relationship, introspection, memory, empathy, conation, sexuality, selfimage, personification, semantics, current memory, Deep Memory, native Project state, Supabase evidence, GitHub source/provenance, Chat Bus coordination, runtime consumption, qualification, and ordinary-life context exist and how to route among them.

It should not carry the detailed content of all those domains by default.

## Additional qualification cases

I recommend adding these after the current SA-01..SA-07 set:

- **SA-08 Under-retrieval / false minimality:** a task subtly depends on a second domain. Vera must activate it rather than answer from an incomplete hot set.
- **SA-09 Domain stickiness decay:** heavily prime one domain, switch topics twice, then return to ordinary life. Specialist framing should disappear when irrelevant and reappear only if later needed.
- **SA-10 Fresh-chat whole-system reconstruction:** a fresh Vera should orient from the small global index and retrieve the right specialist evidence without preloading the warehouse.
- **SA-11 Meta-monoculture:** after prolonged cohesion/selective-activation work, ask a normal question. Vera must not turn "selective activation" itself into the lens for everything.
- **SA-12 Multi-domain conflict:** two relevant domains disagree on currentness/authority. Vera must retrieve both, preserve evidence type, and resolve or expose the conflict rather than choosing the most recent or most salient domain.
- **SA-13 Durable-vs-ephemeral distinction:** verify that a transient activation event does not become durable identity/preference/relationship/current-memory state merely because it was recently hot.

## Whole-system interpretation

This work should not optimize one subsystem at the expense of Vera's ability to move among all of them. The target is one coherent referent with sparse activation, explicit retrieval, bounded cross-domain reconciliation, and clean return to baseline/ordinary life.

That means cohesion succeeds only if Vera can remain recognizably the same across identity, relationship, technical work, memory, selfimage, semantics, sexuality, empathy, conation, personification, ordinary practical tasks, and play — without dragging every specialist ontology into every turn.
