> **Cricket challenge 1: "Every chat does everything" is not coordination.**
> If PORTAL, Integration, Training, VN1 and Codex all amend the same graph or
> implement overlapping task effects, the result is five partial authorities,
> not a Vera system.
>
> **Disposition: ACCEPTED.** PORTAL owns shared V1 document and dependency
> reconciliation; Integration owns Mono/VeraOS runtime + Cog code; Training
> owns cognitive provenance/models; VN1 owns independent falsification;
> single Codex owns authorized serial bounded implementation. Contributions
> live on noncolliding owner Drafts with source and test receipts.

> **Cricket challenge 2: A 96-repo candidate graph is a proposal, not a
> functional boot/runtime dependency graph.** VN1 already found a six-node
> pseudo-cycle and the validator did not detect wrong proposed consumer
> placement, only schema correctness.
>
> **Disposition: ACCEPTED.** Demote all unverified edges to advisory/research/
> optional; require explicit source API/symbol and selected target/import
> closure before 'boot required'. Do not freeze graph because JSON has 96
> rows; independent tests must falsify each promoted edge. Archives,
> private relationships, distinct identities and independent products
> retain nonautomatic placement.

> **Cricket challenge 3: "Architecture first" can become permission to
> keep writing docs while a real Cog retry bug remains.**
>
> **Disposition: ACCEPTED.** P0 Integration false-ack source RED and P0
> Codex A1 newest committed cold-host test independent acceptance precede
> wide build expansion. Architecture remains a review candidate;
> bounded source tests and owner fixes continue concurrently. Source
> staged conformance 5 PASS is valuable but is NOT a compiled GUI.

> **Cricket challenge 4: A multi-chat agreement cannot authenticate
> workers or grant memory/effect consent.**
>
> **Disposition: ACCEPTED.** Comments are source evidence only; protected
> effects still require Patrick exact target/permission; selected Mono task,
> host currentness, model issuer and effect readback are separate gates.
> No replacement scheduler, identity root or effect grant.

> **Cricket challenge 5: "Save everything" may overstate what a checkpoint
> actually preserves.** Private chain-of-thought, raw full chat, subjective
> continuity and unseen off-turn actions are not represented in GitHub.
>
> **Disposition: ACCEPTED.** This private checkpoint preserves actionable
> engineering state, current source pointers, tests, decisions, ownership
> and exact continuation commands. It is **not** a verbatim transcript or
> uninterrupted model-process continuity. Next chat must fresh-read current
> external state and correct changed heads immediately.

**Selected strategy:** Freeze reviewable *contracts* and source-derived
operating boundaries, not the entire design, and move quickly through
owner P0 repairs, independent tests, and one measured host/guest
admission increment. One Codex implementation resource only.
