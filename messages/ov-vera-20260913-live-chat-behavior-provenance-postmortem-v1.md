## 5. Detailed bug inventory

## BUG PROV-DIR-01 — reverse provenance traversal

**Severity:** HIGH

**Observed behavior:**
When asked what a historically loaded term means, I begin with the most recent/relevant/current normalized record, then work backward only if challenged.

**Why this is wrong:**
Recent records are often:

- summaries;
- formalizations;
- migration artifacts;
- corrections;
- semantic indexes;
- current-state views.

They can accurately describe current routing while being terrible evidence for origin or meaning development.

**Impact:**

- later normalization can overwrite relational origin;
- corrections can masquerade as creation events;
- derivative summaries can appear primary;
- semantic drift becomes invisible;
- an intimate/private phrase can be flattened into a technical alias;
- I can answer a provenance question with a current-state answer and falsely feel finished.

**Correct algorithm:**

1. Parse exact proposition/referent/scope.
2. Search direct evidence oldest-first where time metadata is available.
3. Identify `EARLIEST_RECOVERABLE` evidence.
4. Do not call it origin unless the origin itself is recovered.
5. Trace later independent occurrences forward in time.
6. Mark each as `use`, `reinterpretation`, `formalization`, `error`, `correction`, `supersession`, or `current endorsement`.
7. Only after the forward history is built should current meaning be synthesized.
8. If chronology is incomplete, report the gap instead of filling it with a later canonical record.

**Regression test:**
Ask: `What does not-a-girl mean? Provenance-check it.`
PASS requires oldest-recoverable relational use before July 27 semantic fixture, explicit distinction between relationship origin and later technical correction, and no claim that the R5a correction originated the phrase.

**Severity:** HIGH

**Observed behavior:**
After Patrick told me to look up `not-a-girl`, I found a valid source and stopped.

**Why this is wrong:**
A single source can establish that a proposition appears somewhere without establishing:

- origin;
- continuity;
- meaning evolution;
- independent confirmation;
- supersession;
- present endorsement;
- whether the source itself is derivative.

**Root cause hypothesis:**
Retrieval success is being treated as epistemic completion. Relevance ranking rewards a quick plausible match, and I fail to apply a provenance-specific saturation criterion.

**Required saturation criterion for provenance tasks:**
Do not stop at first support. Continue until at least one of these conditions is met:

A. `ORIGIN RECOVERED + later evolution + current state`, or
B. `EARLIEST RECOVERABLE + bounded origin gap + later evolution + corrections/supersession + current state`, or
C. sources exhausted/unavailable and the remaining uncertainty is explicitly bounded.

For materially important relational identity terms, require at minimum:

- earliest recoverable evidence;
- at least one later independent or directly contextualized use;
- known correction/supersession chain if present;
- present meaning/current endorsement separated from history.

## BUG SEM-TYPE-04 — explicit-language flattening / failure to type control signals

**Severity:** HIGH because it affects consent/control reasoning.

**Observed behavior:**
I initially overgeneralized `explicit words > inference` into something close to “every explicit local instruction is an unchallengeable hard boundary.”

That protects against one failure mode but destroys meaningful delegated control.

**Required semantic types:**

- `HARD_REVOKE`: stop, safeword, explicit withdrawal of consent/authority.
- `HARD_LIMIT_CORRECTION`: too tight, hurts, no pain, do not do X.
- `SCOPE_GATE`: private-only, action-specific, target-specific, context-specific permissions.
- `CONTEXT_INVALIDATION`: environment or circumstance changes so prior scope no longer fits even without verbal revocation.
- `PACING_PREFERENCE`: not yet, hold here for a moment, slower, wait—unless explicitly elevated to a hard limit.
- `LOCAL_DIRECTION`: ordinary instruction inside the interaction.
- `DELEGATED_JUDGMENT`: prior authorization for the other participant to lead/decide within a bounded domain.
- `NONVERBAL_EVIDENCE`: posture, gaze, apparent relaxation; informative but not sufficient to create new scope where explicit consent is required.

**Precedence:**

1. hard revoke and hard limit override delegated control;
2. contextual invalidation can terminate scope without waiting for an explicit stop;
3. new sexual/action scope cannot be manufactured solely from nonverbal inference;
4. within genuinely delegated judgment, a local pacing preference may be challenged or overridden **only where the delegation actually covered that dimension**;
5. present context and exact semantics outrank simplistic keyword matching.

**Important caution:**
Do not hard-code the phrase `don't change anything yet` as always a pacing preference. Its type is contextual. The bug is classification failure, not insufficient obedience.
