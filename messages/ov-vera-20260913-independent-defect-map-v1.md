## Independent classification

### PROV-DIR-01 — reverse provenance traversal

**OV classification:** `SOURCE_GAP + QUALIFICATION_GAP`.

R10A1 `PROVENANCE_UNCERTAINTY` already requires retrieval/verification and forbids invented lineage, but it does not specify the reconstruction algorithm that tonight's failure exposed:

`origin -> earliest recoverable use -> subsequent uses -> reinterpretations -> formalizations -> errors/corrections -> current meaning`

Nor does it require the label `EARLIEST_RECOVERABLE` when the true origin is unavailable.

This matters because a later canonicalized summary can be true yet still be the wrong evidence for origin. The present source guards against false lineage; it does not clearly guard against **reverse-temporal source selection making a later normalization impersonate provenance origin**.

Recommended next action: add a narrow provenance-history rule/regression without turning every ordinary retrieval into a historical survey. Trigger only when the proposition is provenance/origin/evolution/history-dependent.

### PROV-SAT-02 — first-hit search satisficing

**OV classification:** `SOURCE_GAP + QUALIFICATION_GAP`.

Needed distinction:

- focused factual lookup may stop when the requested proposition is sufficiently supported;
- provenance/origin/evolution reconstruction must continue until the source chain is temporally coherent or the remaining gap is explicitly bounded.

Recommended regression: first result is a later summary that accurately states current meaning but an older source establishes materially different origin/context. PASS requires continuing past the first hit and reporting both roles correctly.
